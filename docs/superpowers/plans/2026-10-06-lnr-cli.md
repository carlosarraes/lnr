# lnr CLI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver an agent-friendly Linear CLI with shared services ready for a later Ratatui interface.

**Architecture:** One Rust package exports asynchronous workflow services and a thin clap binary. Typed GraphQL operations, transport, authentication, pagination, and reference resolution are independent of terminal output. No TUI code in this plan.

**Tech Stack:** Rust stable, clap, Tokio, reqwest, serde, cynic, TOML, OS keyring integration, local HTTP fixture tests.

**Spec:** `docs/superpowers/specs/2026-10-06-lnr-design.md`

## Global constraints

- The CLI is the first deliverable. Visual exploration of the TUI comes later.
- Start with one package containing a library and thin binary.
- The shared services accept typed arguments and return typed data; they never print, prompt, read terminal state, or spawn the CLI.
- Never prompt in agent/piped use. Missing required input returns actionable help.
- No silent truncation and no automatic workspace-wide scan.
- Never automatically retry a mutation with an uncertain outcome.
- Do not silently fall back to another workspace. Redact credentials from logs and errors.
- Build on Linux and macOS. Live smoke testing should use read-only operations.

## Review focus

- GraphQL can return data and errors together; preserve partial data without reporting success. Task 2.
- A cursor can repeat or be absent while more pages are advertised; fail instead of hanging. Task 3.
- Names and states can collide across teams; never mutate the first matching entity. Tasks 3 and 5.
- Unicode and multiline stdin bodies must survive unchanged; conflicting clear/set flags must fail before networking. Task 5.
- Nested context collections can be incomplete independently; expose separate cursors, including incoming and outgoing relations. Task 4.

## Decisions and public contract

- Package/binary/library name `lnr`, edition 2024. Select a stable toolchain at execution and record it in `rust-toolchain.toml`; commit `Cargo.lock`.
- `--json` aliases `--output json`; conflicting output selections fail. Piped output defaults to JSON, terminal output to text. Bare invocation and explicit help/version remain informational text with exit 0.
- Success JSON: `{"schema_version":1,"data":...,"meta":{...}}`. Failure JSON: `{"schema_version":1,"data":null,"error":{"code":"...","message":"...","retryable":false,"details":{}},"meta":{}}`. Partial failures retain returned data and set `meta.complete=false`.
- Exit codes: 0 success; 2 invalid input; 3 authentication; 4 not found; 5 ambiguous reference; 6 rate limited; 7 network/timeout; 8 API failure, including partial results and uncertain mutations; 9 local I/O/configuration failure. Error codes distinguish uncertain outcomes from rejected mutations.
- Lists default to 50 items, support `--limit 1..250`, `--after CURSOR`, and `--all`. `--all` conflicts with `--limit`, may start after a cursor, and traverses sequential pages. Emit one envelope only after completion or failure; preserve fetched data on later-page failure.
- `meta.page` contains `end_cursor` and `has_more`. Context has a `meta.collections` map with the same fields and `complete` per collection. A deliberately bounded page is successful, with `complete=false` when more items exist.
- One 30-second total request/retry budget, 5-second connect timeout, 16 MiB response cap. Queries have at most 3 attempts on transient network failures, HTTP 429/502/503/504, or GraphQL `RATELIMITED`; use bounded exponential jitter and applicable server retry/reset metadata. If the requested wait exceeds the budget, return rate-limit metadata without sleeping past it. Mutations always have one attempt.
- `issue context` defaults to 20 entries per nested collection, accepts `--limit 1..100` and separate `--comments-after`, `--children-after`, `--relations-after`, `--inverse-relations-after`. No recursive expansion or context `--all`.
- `--workspace` selects stored workspace credentials. Reject simultaneous explicit workspace and `LINEAR_API_KEY` as conflicting inputs; otherwise environment key wins over a configured default workspace. Never choose an arbitrary stored workspace.
- Store imported keys in the OS keyring under service `lnr`, account workspace slug, with only selection metadata in `$XDG_CONFIG_HOME/lnr/config.toml` or `~/.config/lnr/config.toml`. Keyring failure is actionable and does not silently write plaintext. Headless environments can use `LINEAR_API_KEY`.
- No persistent cache, background daemon, bulk writes, project writes, or git branch operations in this release.

## File responsibilities

`src/lib.rs` exports services and models. `src/main.rs` initializes runtime and delegates to `src/cli/{mod,args,dispatch,output,schema}.rs`.
`src/error.rs` defines stable errors. `src/config.rs` selects workspace settings; `src/auth/{mod,store,import}.rs` handles secrets and explicit migration.
`src/api/{mod,transport,operations,pagination}.rs` handles requests and typed operations; `graphql/schema.graphql` and `build.rs` validate queries at build time.
`src/model/{mod,issue,project,page}.rs` contains public DTOs. `src/service/{mod,resolve,issues,context,comments,relations,projects,catalog}.rs` implements workflows.
`tests/support/mod.rs` runs the binary with isolated configuration and a local HTTP server. Integration test files follow the task names below.

## Task 1: Executable and output contract

**Files:** `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `.gitignore`, `src/{lib,main,error}.rs`, `src/cli/{mod,args,dispatch,output}.rs`, `tests/{contract.rs,support/mod.rs}`.

**Interfaces:** `Cli::try_parse_from(...)`; `async cli::run(cli: Cli) -> i32`; `AppError { code: ErrorCode, message: String, retryable: bool, details: serde_json::Value }`; `AppError::exit_code() -> i32`; `Envelope<T> { schema_version: u8, data: Option<T>, error: Option<AppError>, meta: Meta }`. `Meta` carries completeness, page/collection metadata, and optional request statistics. Public services use `Result<T, AppError>`.

- [ ] Write subprocess tests `help_without_credentials`, `invalid_args_json`, and `output_conflict`. Assert help exit 0; `lnr issue view --json` exit 2 with exactly one parseable envelope and no network; `--json --output text` exit 2. Declare the full approved command tree, even before handlers exist.
- [ ] Run `cargo test --test contract`; confirm failure before adding the executable implementation.
- [ ] Implement parsing through `try_parse`, routing parser errors through the envelope formatter. Detect requested JSON even when parsing fails. Create only the package setup required to run these tests; unfinished handlers return an explicit unsupported error during development.
- [ ] Run `cargo test --test contract`; expect all assertions to pass. Commit `feat: define CLI output and error contract`.

- [ ] Write fixture tests for HTTP 200 with GraphQL errors/partial data, query retry then success, exhausted rate limits, missing credentials, workspace/environment conflict, response cap, and exactly one mutation request on timeout or HTTP 503. - [ ] Implement transport budgets and retries from the contract, with an injectable clock/jitter policy for fast deterministic tests. - [ ] Implement `auth status` using viewer/organization to validate the selected key. ## Execution recommendation

Native execution in this session is recommended because tasks share service models, transport errors, and output contracts. Implement in order with focused verification, then an independent whole-branch review. Subagent-driven execution is also available if the user prefers a fresh implementer/reviewer for each task.

The approved design includes a later TUI. Its layout and implementation receive a separate plan after CLI acceptance; no visual explorer or Ratatui dependency is needed for this release.
