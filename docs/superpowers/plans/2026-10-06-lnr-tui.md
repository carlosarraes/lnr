# Project overview TUI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Make interactive `lnr` open the approved, read-only project overview with real Linear data.

**Architecture:** Reuse the authenticated Rust service layer. A synchronous application state machine emits requests; cancellable Tokio tasks return typed results through a channel. Ratatui renders state without network access, while a terminal guard owns setup and restoration.

**Tech Stack:** Rust, Tokio, Ratatui, Crossterm, existing GraphQL/HTTP transport and fixture server.

**Spec:** `docs/superpowers/specs/2026-10-06-lnr-tui-design.md` (read before this plan).

## Global constraints

- Keep version 0.0.1 and Rust 1.94 minimum; retain Linux/macOS support.
- First TUI is read-only. No browser runtime, subprocess CLI calls, or writes to Linear.
- Match approved `project-overview-v7-quiet.html`: spacious list, progress, details below, hidden filters, short footer. No card layout or view switch.
- Preserve CLI flags, JSON envelopes, exit codes, credential selection, and noninteractive behavior.
- Read project progress as Linear's fraction; display `0.5` as `50%`. Missing is unavailable, never zero.
- Page explicitly. Never present loaded counts as workspace totals or infer absent involvement information.
- Minimum usable viewport is 60 columns by 18 rows. Smaller screens show a resize message and retain exit/help handling.

## Review focus

1. A slow response arriving after a scope change must not overwrite the current results (task 2/4).
2. Duplicate names, multiple pages, and unknown pagination metadata must not hide projects or claim completion (task 1/2).
3. Long Unicode text, control sequences, and extreme terminal sizes must not corrupt layout or execute terminal controls (task 3).
4. Keychain/auth failure, refresh failure, and cancellation must leave the interface usable and preserve prior data (task 4/5).
5. Error or panic after partial terminal setup must restore terminal state; redirected invocations must never enter raw mode (task 5).

## File boundaries

- `src/service/project_overview.rs`: richer project reads and filter/catalog queries, separate from existing CLI argument semantics.
- `graphql/operations.graphql`, `src/api/checked.rs`: schema-checked operations for the overview.
- `src/tui/state.rs`: state, navigation, filter drafts, selection, request/result application.
- `src/tui/render.rs`: layout, styling, scroll positions, sanitized display text.
- `src/tui/data.rs`: service request adapter and cancellable task ownership.
- `src/tui/terminal.rs`: terminal setup/restoration.
- `src/tui/mod.rs`: event loop and launch entry point.
- `src/cli/mod.rs`, `src/lib.rs`: interactive startup wiring.
- Tests alongside modules for pure state and layout; HTTP and process tests under `tests/`.

## Task 2: Application state and keyboard behavior

**Files:** Create `src/tui/mod.rs`, `src/tui/state.rs`; modify `src/lib.rs`, `Cargo.toml`, `Cargo.lock`.

**Interfaces:** `App::new() -> App`, `App::handle_key(KeyEvent) -> Vec<Request>`, `App::apply(Response)`. Define `Request { generation: u64, kind: RequestKind }`, `Response { generation: u64, result: Result<Payload> }`. Request kinds: Catalog; Projects with OverviewFilter/PageRequest; Issues with project ID/PageRequest; Issue with issue ID; Comments with issue ID/PageRequest. Payload variants carry their corresponding typed catalog, project page, issue page, Issue, and comment page. Store request kind alongside in-flight generation to distinguish page append, replacement and errors. Keep independent request generations for catalog and active content.

- [x] Resolve Ratatui/Crossterm releases compatible with Rust 1.94 using official documentation/package metadata, lock dependencies, and add module exports needed for tests. Do not raise MSRV.
- [x] Write state tests: arrows and j/k move exactly one row and clamp; selection survives refresh by ID; empty lists have no selection; Enter/Escape follow overview → issues → issue and back; returning restores the parent list and selection.
- [x] Write state tests: `m` resets page and changes scope; `/` edits a draft, Enter applies, Escape cancels; `f` edits a separate draft, Tab changes group, arrows move, Space toggles, Enter commits and Escape cancels. PageUp/PageDown scroll details, `r` refreshes, `n` requests only an available next page, `?` toggles help, `q` quits overview and Ctrl-C exits from every state.
- [x] Write state tests: stale responses are ignored; append deduplicates IDs and preserves selection; repeated cursors and unknown page metadata cannot imply completion; refresh errors preserve data and successful-refresh timestamp. Scope change must not display old rows as belonging to the new scope.
- [x] Run `cargo test tui::state`; confirm failures before implementing state transitions.
- [x] Implement state and requests with ordinary enums and structs. Preserve separate parent views and detail scroll positions. Track loading, refresh, empty, failed and partial states explicitly; do not clone an entire application per keypress.
- [x] Run `cargo test tui::state`; require pass. Commit `feat: add TUI navigation and request state`.

Review-focus cases each have an owning test. No product code is changed by this plan.
